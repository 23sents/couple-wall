# Рядом (CoupleWall)

Приложение для двоих: общий рисунок, который ложится на **главный экран и экран блокировки обоих телефонов**,
плюс парные обои из одной картинки.

* Рисуете пальцем в приложении — рисунок появляется у партнёра на экранах (дебаунс, не чаще раза в 8 с).
  Рисовать пальцем прямо на заблокированном экране Android приложениям не позволяет, поэтому рисуют в приложении,
  а результат ставится обоями.
* Кнопки «домик» и «замок» на панели рисования включают показ рисунка на главном экране / экране блокировки.
* Парные обои «Парные · он» и «Парные · она»: две половинки одной картинки, рядом они складываются целиком.
* 13 обоев, сгенерированных кодом, и своё фото.
* Иконки интерфейса — векторные (SVG), без эмодзи.

## Защита

| Уровень | Что делает |
|---|---|
| Шифрование | Код пары (20 символов, 100 бит) → ключ AES-256-GCM. Сервер видит только шифртекст. |
| Тема на сервере | Имя темы — хеш кода, угадать нельзя. |
| Токен пары | Из кода выводится отдельный токен; сервер хранит только его хеш и привязывает тему к нему при первом использовании. Знать имя темы недостаточно. |
| Ключ сервера `APP_KEY` | Без него сервером нельзя пользоваться: чужие не смогут занять ваш Railway. |
| Лимиты | По IP и по теме, блокировка при подборе ключа, 4 КБ на сообщение, ограничения на число тем, подключений и хранимых сообщений. |
| Сеть | Только HTTPS (в приложении запрещён обычный HTTP), сервер отвечает 426 на небезопасные запросы. |
| Приложение | `allowBackup=false`, экран «Пара» закрыт от скриншотов и превью в списке приложений. |

`APP_KEY` зашит в APK, поэтому это защита от чужого использования сервера, а не секрет пары: приватность рисунка
держится на шифровании и токене пары. Если ключ утёк, смените `APP_KEY` на Railway и в GitHub, пересоберите APK.

## Сервер на Railway

Код в папке `server/` (Node 20+, без зависимостей).

1. Railway → **New Project → Deploy from GitHub repo** → этот репозиторий.
2. В настройках сервиса: **Root Directory = `server`**.
3. **Variables**: `APP_KEY` = длинная случайная строка (не короче 16 символов). Без неё сервер не запустится.
4. По желанию, чтобы история переживала перезапуски: добавьте **Volume** с точкой монтирования `/data` и переменную `DATA_DIR=/data`.
5. **Settings → Networking → Generate Domain** — получите адрес `https://….up.railway.app`.
6. Проверка: `https://ваш-адрес/health` отвечает `ok`.

Необязательные переменные: `MSG_TTL_HOURS` (72), `MAX_MSGS_PER_TOPIC` (500), `MAX_TOPICS` (2000),
`IP_PER_MIN` (240), `TOPIC_PUBLISH_PER_MIN` (90), `AUTH_FAIL_LIMIT` (8), `AUTH_LOCK_MIN` (15).

Тесты сервера: `cd server && npm test`.

## Сборка APK

Релиз собирается GitHub Actions при пуше тега `v*` (или вручную: Actions → Release → Run workflow).

В **Settings → Secrets and variables → Actions** задайте:

* variable `RELAY_URL` — адрес сервера, например `https://имя.up.railway.app`
* secret `RELAY_KEY` — тот же `APP_KEY` (**только если репозиторий приватный**)

Пока репозиторий публичный, не задавайте `RELAY_KEY`: ключ попал бы в APK, который может скачать кто угодно.
Вместо этого введите адрес и ключ прямо в приложении один раз на каждом телефоне: вкладка «Пара» → «Сервер».

APK подписан отладочным ключом (для установки «из файла»).

## Протокол

Ядро (`app/.../core/`) — чистый Kotlin с юнит-тестами: `gradle testDebugUnitTest`.
Штрихи нормализованы (0..1), квантуются в 16 бит, сжимаются deflate, шифруются AES-GCM и пакуются в сообщения
меньше 3400 символов.
